We went looking for a search MCP server that wouldn't force us to stitch together three or four providers just to get web, news, and image results. Brave's official server covers all of that under a single API key. Brave builds and maintains it themselves, MIT licensed, currently sitting at roughly 1.4k GitHub stars. It runs on Brave's own independent web index rather than reselling someone else's results, and it exposes eight distinct search modes. Below we cover setup, the full tool list, current pricing, and how it holds up against Exa, Firecrawl, and Perplexity when your agent has to search the live web.

## What Does the Brave Search MCP Server Do?

The repo lives at brave/brave-search-mcp-server on GitHub under an MIT license. It hands an AI agent direct access to Brave's own search index. For agent workloads that buys you three things worth having: ranking behavior that stays consistent enough to tune your prompts around, one network hop between the query and the results, and a flat per-request price you can forecast before you scale the traffic up.

The server ships as an npm package, @brave/brave-search-mcp-server. At around 1.4k stars it's one of the more established official search integrations in MCPFind's directory. We index 1,973 search-category servers, and most of them are thin community wrappers or single-purpose tools. Brave's bundles eight separate search modes behind one API key and one server process: plain web search, news, images, video, local business listings, and an LLM-context summarizer.

## How Do You Get API Access and Set Up the Brave Search MCP Server?

Start with an API key. Sign up at brave.com/search/api, register through the API dashboard, then generate a key under your account's API Keys section. New accounts get $5 in credits automatically, which works out to roughly 1,000 requests on the Search plan before anything actually bills. You do have to put a card on file. It's an anti-fraud check, and Brave doesn't charge it unless you burn through that credit.

Key in hand, set it as an environment variable and point your MCP client at the server:

```json
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "@brave/brave-search-mcp-server"],
      "env": {
        "BRAVE_API_KEY": "your-api-key-here"
      }
    }
  }
}
```

That config uses STDIO, the default transport. Want to run it as a shared remote service instead of a per-client local process? Pass `--transport http`, or set `BRAVE_MCP_TRANSPORT=http`. Brave also publishes a Claude Desktop-specific setup guide on their API docs site if you'd rather follow the vendor's own walkthrough.

## What Tools Does the Brave Search MCP Server Expose?

Eight tools ship with the server, and each maps to a distinct Brave Search API endpoint, so all eight do genuinely separate work. brave_web_search handles standard queries. brave_news_search, brave_image_search, and brave_video_search cover their respective media types. Business listings and points of interest come back from brave_local_search and brave_place_search. brave_summarizer condenses a result set into a shorter synthesized answer, while brave_llm_context formats results for downstream reasoning by an agent, which is a different job than formatting them for a human to read.

That range is where Brave pulls away from narrower search servers. An agent doing local business research doesn't need a second server for it, since it's the same eight-tool package. Most competing search MCP servers in the directory expose one or two tools at most, so an agent switching between search types elsewhere usually has to switch servers entirely, where here it's a different tool call inside the same one. For a workflow that touches three or four search types in one session, that's one API key and one config block to keep working instead of four.

## How Does Brave Search Compare to Other Search MCP Servers?

Brave, Exa, Firecrawl, and Perplexity solve different search problems. Pick the wrong one for your agent's task and you waste tokens and API budget both. Brave does classic keyword and index search: it matches query terms against its own web index and returns ranked results for the agent to reason over. That's the right shape when your agent needs to see multiple sources and judge them itself.

Firecrawl works a level deeper into the page. It crawls and scrapes, and what lands back in the agent's context is the full body content of the document itself. Perplexity's Sonar-based server runs the other direction and skips the ranked list entirely, handing back a synthesized answer with citations attached. Less reasoning work for the agent, and the material it reasons over is a conclusion somebody else already reached. For discovery queries of the "find things like this" variety, [Exa's server](/servers/ai-exa-exa) leans on neural or semantic matching, which beats exact keyword lookup at that particular job.

So if your agent needs control over how results get used instead of a pre-digested answer, Brave is the more complete fit for most agent workloads. MCPFind's [search category](/categories/search) has the full list of 1,973 servers we track in this space.

## When Should You Pick Brave Search Over a Different Search Server?

Reach for Brave when your agent needs raw control over search results across more than one media type, at a predictable per-request price. That combination is rare enough in MCPFind's directory that we'd call the setup time worth it even for teams already running another search server for a narrower task.

If your agent's job is closer to answering a question outright than to searching and reasoning over results itself, start with [Perplexity's MCP server](/blog/perplexity-mcp-server-search-guide), which hands back a synthesized answer in place of a ranked list. Enterprise document or log search is a different shape of problem, and [Elasticsearch's MCP server](/blog/elasticsearch-mcp-server-guide) fits it better. New to the protocol? [Our plain-English guide to what MCP is](/blog/what-is-mcp) covers the basics this guide assumes. And none of these are mutually exclusive. We've seen teams run Brave for general web and local search alongside a narrower server for one specific data source, since MCP servers are cheap to add and an agent only calls the tools relevant to a given query.

## Frequently Asked Questions

### Does the Brave Search MCP server use STDIO or HTTP transport?

Both. STDIO is the default when you run the server locally. HTTP is opt-in: flip it on with the --transport http flag or the BRAVE_MCP_TRANSPORT=http environment variable. Most solo setups never need that flag. It earns its keep when one deployment has to serve a whole team, or several machines, off a single running instance.

### How many API requests do I get before Brave Search charges me?

Billing kicks in the moment you spend past the $5 credit every new account starts with, and on the Search plan that credit stretches to roughly 1,000 requests. Brave asks for a card at signup purely to screen for fraud. It sits untouched until you cross that line.

### Can the Brave Search MCP server search for local businesses, not just web pages?

Yes. Say your agent needs three coffee shops open near a downtown address, then hours and a rating for the one it picks. brave_local_search handles the first half of that, brave_place_search the second. Send the same query through plain web search and you get articles about coffee shops.

### Does Brave Search resell Google or Bing results?

No. Brave crawls the web itself and serves results from the index it builds.
