Use [GitHub's official MCP server](https://github.com/github/github-mcp-server) to connect Claude Code to repository tools. The old `@modelcontextprotocol/server-github` npm example in earlier versions of this guide is not the current official implementation.

*Docs reviewed October 17, 2026 from [GitHub setup documentation](https://docs.github.com/en/copilot/how-tos/provide-context/use-mcp-in-your-ide/set-up-the-github-mcp-server) and the [official repository](https://github.com/github/github-mcp-server). This guide is docs-derived; MCPFind did not authenticate or run a repository task.*

The matching [GitHub server listing](/servers/io-github-github-github-mcp-server) links to the official implementation.

## Choose a supported connection

GitHub recommends its hosted server for most users. For remote Claude Code, [GitHub's Claude installation guide](https://github.com/github/github-mcp-server/blob/main/docs/installation-guides/install-claude.md) documents a personal access token (PAT) in the Authorization header. OAuth support depends on the client and its registered application; do not assume a bare endpoint enables OAuth in Claude Code. Local Docker or binary deployment remains a separate choice for customization or specific security requirements.

Review the account, repository access, and organization controls before connecting. Enable only the needed toolsets and read-only mode for lookup work, following [GitHub's tool configuration documentation](https://github.com/github/github-mcp-server). An organization can restrict OAuth applications, PATs, or MCP access; changing authentication does not bypass those controls.

## Add a project configuration

Save the following as `.mcp.json` at your project root. If it already exists, merge the `github` entry into its existing `mcpServers` object rather than replacing other entries.

```json
{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp",
      "headers": {
        "Authorization": "Bearer ${GITHUB_PERSONAL_ACCESS_TOKEN}"
      }
    }
  }
}
```

Make a least-privilege PAT available as `GITHUB_PERSONAL_ACCESS_TOKEN` in the environment that launches Claude Code, using your secret manager or local secret setup. The configuration references the variable; never commit the token value. Review the token's repository selection and organization restrictions before use.

Start Claude Code from that environment and project, then open `/mcp` to inspect the GitHub entry. Follow the current [client configuration documentation](https://code.claude.com/docs/en/mcp) for environment-variable expansion, project approval, and storage.

## Verify one repository operation

In a terminal, inspect the configuration:

```bash
claude mcp get github
```

Within Claude Code, open `/mcp` and inspect the connection. Then use a known issue as the check:

> Read issue 12 from OWNER/REPOSITORY using the GitHub MCP tools. Return its title, state, and link. Do not write comments or modify anything.

Replace the repository and number with an issue you can verify yourself. A connected status tests the connection; matching the issue tests the account, repository access, and tool result.

If authentication fails, check the PAT's validity and the environment available to the client. If a repository request fails, review account access, selected repositories, toolsets, and organization restrictions before broadening access.

## Keep the workflow small

Start with issue lookup or pull-request reading. Add write permissions only after identifying a task that needs them. If your existing `gh` workflow already handles a job well, there is no requirement to replace it; evaluate MCP against the same known repository task.
